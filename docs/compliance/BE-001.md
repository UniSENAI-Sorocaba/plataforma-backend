## Correções feitas para fechar o AC-01

O critério 1 não passava na `develop` antes desta branch: 140 testes, 34 com erro. Foram duas causas, ambas
corrigidas aqui em commits separados:

1. `JpaPasswordRecoveryAccountLookup` e `JpaPasswordRecoveryTokenRepository` (AUTH-10-BE, #42) exigiam
   repositórios Spring Data na criação do contexto, mas os testes HTTP e de contrato rodam sem `DataSource`.
   Os adaptadores agora resolvem o repositório quando o método roda (`ObjectProvider`).
2. `jackson-dataformat-yaml` estava com escopo `test` no `pom.xml`, o que o removia do jar. Com o Swagger
   ligado (perfil `local`, usado pelo Docker Compose) a aplicação caía com `NoClassDefFoundError`.

## Warnings/justifications

1. **Estrutura por camada.** A issue pede um pacote por módulo (`auth`, `academic-pi`, `extension`, `assets`,
   `institutional`). O código está organizado por camada, e os módulos são identificados pelo schema. Pelo
   MH-ARCH-002 a decisão precisa de ADR ou aprovação dos Technical Leads.
2. **Dois pacotes raiz.** `plataforma` e `br.senai.plataformadigital` convivem (código dos PRs BE-010 e BE-019).
   O `LayerDependencyTest` cobre apenas `plataforma`.
3. **CI remoto.** O gate remoto de spec-compliance não foi executado: a tag `governance-v0.1.0` não existe no
   repositório de governança. O job "Contracts and producer tests" precisa rodar no PR para confirmar o AC-01
   fora desta máquina.
4. **Lint.** Não há Checkstyle, PMD ou SpotBugs configurado no `pom.xml`. A verificação de build e de testes
   roda nos workflows existentes (`mvn verify`), mas não há um passo de lint dedicado.
5. **Autorização.** Desde a BE-010, rotas fora do catálogo respondem 401, inclusive o Swagger e os CRUDs
   entregues no PR #36. Isso não é regressão desta task, mas muda o que o README antigo prometia; o README foi
   atualizado.
